# Mixed-document review

The adapter adds a typed `document_integrity_flags` field to the existing extracted snapshot. An omitted field (internal None) identifies a historical or otherwise unassessed snapshot. The serializer omits None, which preserves the original wire and source-fingerprint shape for historical records. Newly grounded mixed documents carry `RASTER_CONTENT_UNRESOLVED`. Newly grounded non-mixed documents carry an empty tuple for this specific check. Empty does not establish broader document authenticity or confirm payment instructions are absent. The field uses a closed literal type and no new table, migration or arbitrary metadata.

The grounder derives the signal from the actual parser route after wire validation. The provider schema remains strict and cannot supply the field, even with an empty list or null. Mixed routing includes native pages mixed with image-only pages as well as individual readable pages bearing unresolved raster content. The parser's bounded routing, visibility and harmless uniform swatch checks are the Phase 6B.2B checks.

In a usable mixed invoice, the signal replaces the blanket missing-bank technical error. Facts and actual evidence are retained. A pure rule adds `DOCUMENT_CONTENT_UNVERIFIED` at Review severity with Accounts Payable as owner and an explicit rendered-document next step. Existing deterministic BLOCK precedence applies. Stored facts are reused by preview and human confirmation, so neither reinterprets or clears the flag. Historical JSON is left as recorded and the previous assessments are not recalculated.

Bank facts remain separate. A missing bank object yields the existing informational reason code with the title “No payment instructions extracted.” Grounding can only independently verify bank details cited on an independently usable native page and supported by its source. Image or mixed-page bank claims stay unverified. An independently verified native discrepancy still blocks even if unrelated raster appears elsewhere. Known printed native details omitted from an otherwise incompatible model response, incomplete bank payloads, unusable results and parser/provider errors still use the existing technical paths.

A nonuniform decorative logo can conservatively request manual review. The route signals unresolved content, with no assertion about the image's financial relevance. Image-only scans already require review through evidence controls and keep that path. Existing generic finding rendering displays the new Review, owner, next action and source PDF. No frontend change was necessary.
