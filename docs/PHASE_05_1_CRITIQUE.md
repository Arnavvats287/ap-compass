# Phase 5.1 — rendered critique, before UI changes

Material: the running local application, four persisted live analyses, and 15 baseline Chrome captures in `tmp/phase051-before` at 1440×1000, 1024×900 and 390×844. No model calls were made. This is an operational application redesign, not a landing page.

- **Hierarchy:** the overview gives total, ready, review, blocked and processing equal weight. The flagged net value reads like a footnote. Prioritize attention without inventing another aggregate or implying savings.
- **Density:** the stretched desktop upload panel contains unused space; the mobile five-count strip consumes roughly 340px. Make the upload naturally sized and counts more compact. The hypothesis of universally excessive canvas is rejected: the recent queue already fills the desktop view; the problem is allocation within it.
- **Typography:** small secondary text dominates the overview and queue. The blocked brief's remaining, requested and excess amounts are as small as routine PO metadata. Increase selected figures and body readability, rather than enlarging everything.
- **Composition:** the source/decision split is useful and stays. At 1024px the queue wraps “Procurement” mid-word; give ownership predictable space and reduce redundant table padding.
- **Memorability:** forest navigation and warm paper are appropriate but insufficiently distinctive. Establish an attention summary and a monetary comparison as the two signature patterns. Reject decorative graphics, gradients and generic card proliferation.
- **Operational usability:** the primary finding and owner are present but lack a clear visual reading sequence. Separate the financial comparison from supporting authorization history; keep every value and the backend's primary reason unchanged.
- **Interaction:** existing keyboard links, real filters and native disclosures work. Improve row/focus affordance and disclosure-open treatment. Do not add hover movement to financial rows, fake progress or automatic expansion animations.
- **Mobile:** content fits and decision precedes document, but overview counts and vertically stacked evidence badges add avoidable length. Compact the count layout and evidence references while preserving long-value wrapping, touch targets and truthful labels.

Direction: **a forest-and-paper finance workbench, with ledger-like comparisons and deliberate attention hierarchy**. Preserve the current product language, source semantics, routes, API behavior, payment disclaimer and every backend result. Use the existing unified tokens, with a stronger numerical scale and restrained surface contrast. No new metrics or workflow actions.

Skill priority: AP Compass usability → Hallmark app/redesign → Vercel interaction/accessibility → Taste critique. Marketing hero structures, one-section-per-screen layouts, photograph requirements, shader scenes and decorative looping interactions are deliberately rejected because they obstruct repeated invoice work.
